# Synthetic Headroom reproduction

This package measures local compression of deterministic, obviously synthetic tool outputs. It contains five fixed variants each for JSON tool output, build logs, and grep hits. No production data, private paths, instructions, credentials, provider requests, or user prompts are used.

## Reproduce

Use CPython 3.13.16 and `uv 0.12.23` with the checked-in lockfile. Direct package pins are Headroom AI 0.40.0 and tiktoken 0.14.0; the copied validated environment also pins Trafilatura 2.3.1, which this benchmark does not import. The lock records 108 package entries, including the local project entry. Downloadable dependency artifacts have SHA-256 hashes in the lock; the local project entry has no package artifact hash.

```text
uv sync --locked --python 3.13.16
uv run --locked python run_benchmark.py --output-dir output
```

The run writes full synthetic input/output trials to `output/trial-details.jsonl`, sanitized per-trial metrics to `output/trial-metrics.json`, an aggregate to `output/summary.json`, and version/configuration data to `output/environment.json`.

## Method

Each fixture is a single `tool` message passed to Headroom's public `headroom.compress()` API. The run pins the local model label `gpt-4o` for Headroom token counting, sets `protect_recent=0` and `compress_user_messages=False`, and disables Kompress model weights with `kompress_model="disabled"`. Structural compression remains active. No provider SDK is called; the model label is not used to make a provider request.

Headroom's `tokens_before`, `tokens_after`, `tokens_saved`, and `compression_ratio` are reported as returned; its v0.40.0 API defines `compression_ratio` as `tokens_saved / tokens_before`. A separate count uses tiktoken 0.14.0's explicit `o200k_base` encoding over compact JSON serialization of the complete message list. These are local serialized-message counts; they are not API billing counts and do not include provider-side message framing.

The gold oracle checks only exact presence of each fixture's predetermined marker substring in compact JSON-serialized messages before and after compression. A surviving marker does not establish that other information survived, that the output is semantically correct, that a task would succeed, or that compression is safe for any real workload.

The fixtures vary deterministically by category and variant number. They are generated by `fixtures.py`; no random number generator or private input generator is used. They deliberately contain repeated synthetic padding and repeated structure to exercise compression. These fixtures are not sampled from a real workload and may overstate savings on less-repetitive inputs. The overall percentage is an unweighted arithmetic mean of the 15 per-trial Headroom ratios. It is descriptive of these fixtures, not a performance guarantee or a generalization claim.

The recorded run used Windows x86_64. Its manifest records Headroom selecting the pure-Python content-detection backend. The reason for that selection was not independently established. This is an observed runtime configuration, not a confirmed software defect. No cross-host run was made to compare detector backends.

## Versioned source basis

Accessed 2026-10-09:

- Headroom v0.40.0 release and public `compress()` result/configuration contract: <https://github.com/headroomlabs-ai/headroom/releases/tag/v0.40.0> and <https://github.com/headroomlabs-ai/headroom/blob/v0.40.0/headroom/compress.py>. These sources establish the release/API behavior documented by the project; they do not establish independent correctness or performance.
- Headroom compression pipeline documentation: <https://github.com/headroomlabs-ai/headroom/blob/v0.40.0/docs/content/docs/how-compression-works.mdx>. This documents the vendor's described pipeline, not an independent validation of it.
- tiktoken 0.14.0 release metadata: <https://pypi.org/project/tiktoken/0.14.0/>. The lockfile pins the exact package artifacts and SHA-256 hashes for the supported environment.
- OpenAI tiktoken model mapping: <https://github.com/openai/tiktoken/blob/0.14.0/tiktoken/model.py> and tokenizer API: <https://github.com/openai/tiktoken/blob/0.14.0/README.md>. The runner also verifies at runtime that the installed `gpt-4o` mapping resolves to `o200k_base`.

The lockfile was copied from the already validated Python 3.13.16 evaluation environment. `trafilatura` is retained as a locked direct dependency in that environment but is not imported by this benchmark.
